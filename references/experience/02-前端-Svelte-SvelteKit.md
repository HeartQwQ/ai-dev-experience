# Svelte / SvelteKit 前端开发经验

适用范围：使用 Svelte 5 / SvelteKit 的项目，以及涉及异步状态、契约消费、安全边界、表单、列表、性能或教程的界面任务。Runes 部分适用于项目已经使用的 Svelte 5 模式；路由与构建按实际 SvelteKit 版本、适配器和托管环境核对，不要求旧项目整体迁移。

本文为经验整理与设计修订。视觉表达和布局方法由[UI 设计](05-UI设计.md)维护，跨系统写入保证与契约源定义由[后端篇](01-后端-Rust-Axum-Tokio.md)维护，检查状态和工程交付由[工程篇](04-工程与协作.md)维护。

## 一、状态、作用域与异步结果

### 1.1 Runes 的分工

能由其他值计算得到的状态，优先用 `$derived` / `$derived.by` 表达；必要外部同步（如订阅非 Svelte DOM API 或 Canvas/GSAP 生命周期）才使用 `$effect`，严禁用多段 `$effect` 相互回写业务状态。事件引起的修改直接放在对应事件路径，便于追踪。

只有驱动视图或响应式计算的值才需要响应式状态。大对象（如长列表只读快照、GeoJSON、图表数据集）只整体替换而不做细粒度属性变更时，优先使用 `$state.raw` 避免深层 Proxy 代理开销。组件的外部输入与回调契约使用 `$props()` 并配合显式 TypeScript 类型声明。

已有服务端缓存（如 TanStack Svelte Query）、父级状态或上下文持有的事实，不另建会漂移的长期镜像；编辑草稿、撤销快照和乐观状态是不同语义，可以单独建模，但需要明确同步与失效条件。

### 1.2 状态按生命周期归属

区分服务端请求、组件树、页面、当前对象、客户端跨页状态和持久化状态。目录集中不等于生命周期正确；不要为了统一 `.svelte.ts` 状态模块目录，把用户状态变成服务端跨请求模块级单例。

**SSR 用户私有数据不能存入跨请求共享的模块变量。** 请求数据、会话和组件上下文按框架能力（`locals`、`page.data`、`setContext`/`getContext`）隔离；客户端共享状态也要清理退出登录、租户和对象切换带来的变化。[SvelteKit 状态管理](https://svelte.dev/docs/kit/state-management#Avoid-shared-state-on-the-server)。

页面草稿以对象/字段等稳定身份定位，离开后丢弃、保留或提示由产品需求决定。对象切换需要销毁临时状态时，可使用 `{#key id}` 等边界，但同时核对焦点、滚动、草稿保留和重建开销；普通派生值更新不靠强制销毁组件。

### 1.3 请求定序、取消与超时

同一位置可能收到乱序结果时，响应写回前核对请求身份与当前作用域。取消旧读取可节省资源，但仍需处理已完成、不能取消或迟到的回调；计数、加载态和错误也只清理本次所属任务。

超时覆盖所需的连接、响应和响应体读取阶段。读取与写入可有不同预算；优先使用标准 `AbortSignal.timeout()` 与 `AbortSignal.any()` 组合取消信号与超时预算。

写操作超时可能意味着结果未知。取消等待不代表撤回服务端写入，重试需结合操作 ID、幂等和结果查询，不能直接当作未执行。

### 1.4 跨端契约消费与边界数据解码

**跨端接口优先消费由后端自动生成的类型契约（Single Source of Truth）：**

- HTTP 接口优先使用 `packages/contracts/` 中由后端 `utoipa` OpenAPI 3.1 导出的 `openapi-typescript` / `orval` 客户端；Tauri v2 桌面端优先使用 `tauri-specta` 生成的严格类型命令绑定。禁止前端手写与后端脱离的接口 DTO 或自行猜测 RFC 9457 错误体结构。
- 外部不受控 JSON、URL 查询参数、粘贴导入与本地存储（`localStorage` / `IndexedDB`）在信任边界使用运行时 Schema（如 Zod / Valibot）或显式类型守卫完成校验后再进入业务类型；单纯的 `as Type` 断言不能替代实际运行时校验。

数值严格解码与容错转换分开，明确空串、`null`、字符串数字和非有限数（`NaN` / `Infinity`）的含义。改名不能掩盖语义变化；确有不同口径时用清楚的命名和用例表达。二进制视图传递保留 `byteOffset` 与 `byteLength`。

### 1.5 状态表达

按真实协议区分未开始、进行中、成功、失败、结果未知等状态，不用“已发请求”证明成功。空数据、筛选无结果、读取失败和权限不足应可分辨，缺值不伪装成零值或最新状态。

有内容时刷新失败可保留已知内容并提示陈旧/重试；编辑能否继续由版本校验和写入安全决定，不一律禁用所有输入。乐观更新只有在产品允许、失败可回退/协调、且结果能正确确认时使用。

## 二、路由、部署、安全边界与数据加载

### 2.1 先识别部署形态

先查看实际配置、适配器、预渲染选项、SSR/SPA 和后端托管规则。新增路由维持已有部署契约，不能把某个静态应用的约束套给所有 SvelteKit 项目。

| 形态 | 需要确认 |
| --- | --- |
| 静态预渲染 | 需产出的路由、动态参数来源、构建数据、输出与深链接托管 |
| SPA / 静态壳（含 Tauri） | fallback 产物、客户端路由、刷新路径、加载与错误体验 |
| 服务端渲染 (SSR) | 运行时适配器、请求数据、会话隔离和部署可用能力 |
| 混合渲染 | 各路由职责、缓存边界与部署支持，避免互相矛盾的配置 |

纯静态预渲染的必要页面需在构建中产出；动态参数按该版本支持的枚举/发现机制处理。SPA fallback 与 strict 的选择取决于方案，不为消除构建报错盲目关闭检查，也不一律禁止 fallback。页面与资源输出可同目录或分开，部署映射必须对应。[官方静态适配器说明](https://svelte.dev/docs/kit/adapter-static)。

### 2.2 页面实例与导航

需要跨页保留输入时，可选框架 `snapshot`、上层草稿状态或保留实例；不需要时按需挂载。隐藏页面/页签仍可能有定时器、订阅和网络副作用，应暂停或隔离这些工作，并从交互与可访问树正确处理隐藏内容。

页签的受控/非受控、单向/双向绑定取决于当前组件 API 和状态归属。明确谁拥有当前值，避免初始化默认值覆盖恢复值；嵌套页签保持独立作用域。

锚点、自定义滚动和浏览器历史先用框架现有能力，只有明确冲突的路由才调整滚动处理。不默认包装全局 `history` 方法。若桥接环境确需兼容修复，要保留接收者、state、参数数量、相对/空地址与异常语义，并覆盖序列化回归。

依赖变化后按实际开发服务器行为重新安装、重启或清理相关缓存；不要把历史依赖优化问题变成所有页面都强制预优化的规定。

### 2.3 加载、缓存、时间与实时更新

服务端数据交给查询缓存（如 TanStack Svelte Query）时，明确 query key、身份/租户作用域、失效和新鲜期，避免复制第二份长期状态。列表与详情分别处理竞态；手动命中缓存也应遵守失效语义。详情是否重取由新鲜度决定，不把“重复点击永不请求”视为正确性目标。

时间字段明确表示时间点还是本地日期/时间。时间点可用带偏移或 UTC 的契约存储，显示时使用 `Intl.DateTimeFormat` 及目标时区规则；存在夏令时或历史时区规则时不能用固定小时偏移代替。避免对已转换值重复加减小时。

实时消息按资源身份分发并失效相关缓存。重连、退避、可见性补查和轮询按业务时效与资源预算设计，去重焦点/在线事件，明确后台行为；不把原项目的重试次数和秒数当作通用默认。

### 2.4 Web 与 Tauri v2 桌面安全基线

- **XSS 与 CSP 防护**：禁止对未经消毒的用户内容使用 `{@html ...}`；SvelteKit 配置 `kit.csp`（采用 `mode: 'auto'` 或显式 nonce/hash 策略），限制外部脚本与内联执行。
- **认证与跨域**：Web 会话优先使用 `HttpOnly; Secure; SameSite=Lax`（或 `Strict`）Cookie，避免将高权限长期私钥明文存入 `localStorage`。CORS 显式配置可信源白名单，禁止带凭据请求（` credentials: 'include'`）配合通配符源。
- **Tauri v2 最小权限（Capabilities ACL）**：桌面端在 `src-tauri/capabilities/` 中按窗口标识声明最小所需权限与文件系统/HTTP 作用域（Scope）；禁止向远程不可信 URL 暴露 Tauri IPC，禁止为图省事开启全量 shell 或任意路径读写权限。

## 三、组件职责与复用

复杂编辑页可以分为加载/组合容器、业务区块和原子控件，但拆分依据应是职责变化、测试与复用收益。简单组件同时取数并展示并不自动意味着必须拆三层。

优先复用现有数值控件、表格原语、反馈与样式变体；局部可复用 UI 片段在同一组件或跨组件间优先使用 Svelte 5 `{#snippet}` 与 `{@render ...}` 组合，减少无状态的零碎包装组件。同构业务布局可以共享区块；不同任务的表格不强求同一个巨型组件，避免通用组件接管所有数据关联和草稿规则。

状态通过 `$props()`、上下文或项目状态机制清楚传递，避免组件偷偷创建同一事实的副本。作用域变化时作废迟到的预览和定位任务，弹层实例按调用归属管理，不强制整个应用只能有一个确认框。

局部重置、批量操作、选中数量与统计分母都以声明的范围计算。布局高度、滚动和加载/错误占位保持一致，具体滚动模型见[UI 设计](05-UI设计.md)。

## 四、大列表、分页、过滤与定位

### 4.1 根据成本选择策略

数据量、传输体积、权限范围、行高变化、展开状态、检索语义和实际测量共同决定虚拟化、分页或服务端查询。行高不定并不自动排除虚拟化，可评估动态测量与复杂度；小列表也不因“性能原则”强上虚拟器。

前端过滤适用于已获授权且体积可接受的数据；大数据、跨全集搜索或权限过滤应考虑服务端。不能为搜索预取未授权的全集。分页大小、按钮/下拉形式和是否保留筛选由任务决定。

### 4.2 虚拟化与移动动画

虚拟列表使用稳定身份，保留可视项和合理缓冲。虚拟器负责布局与测量，动画在独立内层进行，避免改变其管理的行高或定位；确有跨视口动画可用临时视觉层，但需不可交互、对读屏隐藏并及时清理。

展开详情按需拉取与缓存，控制可同时展开的重量级内容。是否恢复展开项、页码和筛选按用户需求决定，不以同一套刷新行为处理所有页面。

### 4.3 自动定位与内容可达

定位用稳定 ID 和当前索引，在 DOM 与测量就绪后执行。筛选让目标不可见时先明确产品行为：提示、调整筛选或保持当前视图，不能擅自悄悄清除用户条件。

用户滚动、触摸、按键或新选择可作废尚未执行的自动定位；卸载后不能回写滚动。宽表首尾内容需真实滚动验证，不能用祖先裁剪与子级溢出可见组合把横向操作关掉。自动化悬停/点击前让目标可达，不靠强制操作绕过遮挡。

## 五、表单、数值编辑与提交

### 5.1 编辑与保存入口

核心编辑应可发现、可键盘操作，不只提供双击。保存可以是整体、分区、逐行或自动保存，取决于用户任务和后端原子单位；入口明确反映作用范围，不强制全部集中页头。

禁用状态提供用户需要的原因，使用标签、描述或可访问提示，不把原因藏在仅鼠标可见的浮窗中。原生 `disabled` 与 `aria-disabled` 的选择按交互语义实现，ARIA 本身不会阻止点击或键盘动作。

### 5.2 数值控件

复用项目已有数值原语，明确单位、范围、步长、精度和舍入。比例是否显示百分号、分母或快捷值由业务决定；不把原项目固定宽度、两位小数和三段式强加给所有数值字段。

键盘与滚轮行为避免意外改值，尤其是页面滚动时；允许用户正常选择文本，不默认所有聚焦都必须全选。达到边界时保持状态和操作一致，不能“看起来可按但静默无效”。输入过程与编辑完成是两种事件语义，调用方明确使用哪一种。

### 5.3 草稿与提交状态机

草稿键可由对象 ID、行 ID 和字段组成，保证作用域唯一。草稿、预览快照、远端基线和审计记录分别建模；标记的来源和含义一致，具体颜色与徽标见 UI 篇。

提交前确认目标、版本和有效值。请求返回只清理仍等于本次已提交值的草稿；期间新增输入保留。旧对象的响应不能清除新对象的输入或错误。

| 提交契约 | 前端必须对应的行为 |
| --- | --- |
| 全批原子事务 | 失败时整批保留；确认成功后按提交快照清理 |
| 逐项/可部分成功 | 逐项记录结果，只清成功项；重试范围和停止条件清楚 |
| 跨系统工作流 | 区分未发送、结果未知、已确认和恢复中，使用操作标识协调 |

跨系统流程的预算、幂等和恢复沿用后端契约，不独立发明一套客户端重试协议。关闭预览可取消读取；已发送写操作不能因组件卸载被假定撤销。清理失败保留原始写入原因与恢复依据。

### 5.4 校验、导入与反馈

**错误信息独立于绑定值。** 不把后端报错写进输入框，再当用户数据提交。前端预检改善反馈，后端仍维护真实约束；双方口径避免漂移。

范围错误说明字段与合法条件，接受全部合法值，不绑定教程或测试中的单一答案。局部重置只处理声明范围；重置是否丢弃草稿或恢复快照要明确。

批量导入说明去重、已存在、非法项和原子性：可部分导入时展示逐项结果，要求原子性时不产生未声明的部分成功。写入结果未知时保留确认线索，不能用“报错后清空”制造重复操作。

## 六、性能、质量与浏览器验收

### 6.1 范围与证据

从实际路由、状态、操作、设备和环境出发。内部登录工具一般不需要公开收录检查；存在公开内容时再纳入。未经证据支持，不为套清单添加 CDN、代码拆分、监控或依赖。

| 证据 | 能支持的结论 |
| --- | --- |
| 真实用户现场/第一方聚合数据 | 指定窗口、设备和样本中的体验分布 |
| 浏览器 trace / 受控实验 | 当前条件下的请求、主线程、渲染和交互瓶颈 |
| 静态源码检查 | 可能影响性能的路径及待验证假设 |

一次浏览器采样不能叫真实用户监控。没有页面或样本时，说明不可用与验证方式，不从总分或资源大小推导未测指标。

### 6.2 测量与优化

先采基线再修改，并在相同输入、登录状态、视口、缓存、节流和版本下复测。初步对照可做至少三次并报告中位数与范围；噪声、长尾或关键容量决策需要更充分样本，三次不是统计充分性保证。

按 trace 区分请求发现、网络、事件处理、渲染和节点量。预取、空闲载入或预热只在预期命中、内存/CPU/流量成本可接受且无业务副作用时采用；不默认隐藏渲染所有重组件。证据不支持收益时撤回无用改动。

Core Web Vitals 的 Good 参考为 LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1；现场按相应样本的第 75 百分位，区分移动与桌面等条件，整体判断需三项都满足。实验室单次值不等同现场通过，缺失样本不是通过。[官方口径](https://web.dev/articles/vitals)。实际任务使用时核对指标是否更新。

### 6.3 检查、Vitest 浏览器模式与记录

静态检查与格式化优先使用 **Biome (`biome check`)** 与 **`svelte-check`**；组件级交互与状态测试优先使用 **Vitest Browser Mode (Playwright Provider) + `vitest-browser-svelte`**，在真实无头浏览器中验证 Svelte 5 Runes 响应式、CSS 容器查询布局、焦点圈定和真实键盘事件，避免 JSDOM 模拟失真。

漏洞扫描结合受影响版本、实际路径与修复兼容性，不用总分证明系统安全。记录范围排除及原因，不把排除第三方挂件后的结果扩大到整个页面。

每条发现记录页面/状态、环境、观测或假设、受影响用户任务、代码位置、建议与验证状态。首次失败和复跑分开，mock 与真实接口分开。

### 6.4 视觉与交互验收

在代表性桌面、分屏与窄屏中实际点击、输入、提交并核对反馈；长名称、首尾列、错误、弹层和键盘都需按影响覆盖。元素存在或可见不等于用户能操作，不能用强制点击掩盖裁剪。

参考图只定义已明确的视觉信息，不能据此推断保存、权限和同步行为。有真实页面才报告渲染验收，否则标注静态检查范围。

## 七、UI 文案

文案服务于当前状态、下一步行动、操作后果和必要风险。能用标签、信息结构或清楚的控件状态表达时，不额外堆解释段落；但首次引导、复杂操作和开发者工具需要的帮助信息可以保留。

避免把开发计划、组件职责或实现理由塞入普通业务界面。技术信息确实影响用户选择时可以说明，例如“仅保存在当前浏览器”关系到跨设备可用性与数据保留，不能因它包含技术词就删除。

使用实际按钮与模块名，错误明确指出可纠正条件。响应式页面少依赖“右上角”等位置描述；同一事项不在多个区域重复警告。保留受众熟悉且精确的术语，不把所有领域词机械改成含糊口语。

## 八、交互教程与引导页

### 8.1 内容与真实功能的关系

教程正文与开发实现文档分开维护；Markdown、CMS 或其他来源按项目选择。若从文件构建目录，可由标题和稳定标识生成导航/锚点，删除或改名后校验引用。标题用于展示，长期链接可以使用稳定 ID，避免仅因改文案就全部断链。

渲染不可信内容时明确 HTML、URL、图片与外链策略，避免可执行链接；构建时内容和运行时上传内容是不同信任边界。长代码和表格允许局部横向滚动，正文适应视口。

目录、标题和练习入口位置依阅读任务设计，不强制固定标题区或统一放右侧。直接访问、历史返回和锚点定位先沿用框架能力，必要时局部定制。

教程优先复用真实展示与控件，操作数据使用隔离样本；演示、练习和真实保存边界明确，不能偷偷调用线上写接口。若是用户明确选择的真实任务引导，则需另外说明权限、影响和退出后状态，不伪装为无副作用练习。

### 8.2 自动演示

需要自动播放时，用统一且可调整的时间轴表达指针、按下、输入、失焦与阅读停顿；不以复杂动画替代任务信息。默认避免无休止循环，用户操作可中断，遵守减少动态效果偏好。

页面隐藏、卸载、作用域切换或布局变化时取消失效动画与定位；异步加载完成后核对演示是否仍有效。区分演示驱动和用户驱动的滚动，不能让自身滚动误触发中止。重播先结束上一轮并恢复该段初始样本。

### 8.3 手动教程

开始前展示目标和练习影响范围，用户开始后再限制到当前步骤；任务卡、弹窗或其他形态按界面需要选择。每步明确操作目标与完成条件，接受满足目标的所有合法输入。

完成后推进不依赖任意阅读计时；纯说明步骤可以由用户确认继续。退出、Esc、暂停和重练的含义一致：暂停保留进度，重练才重置所声明范围；是否保留练习输入需清楚。

遮罩、框选与提示跟随实际目标，目标及必要上下文可见，提示不挡输入与按钮。焦点限制不能把用户困在消失的元素上；找不到目标时保留退出和恢复入口。离开后恢复滚动与合理焦点。

### 8.4 制作与验收

先核对真实页面的字段、顺序、按钮条件、权限和提交范围，再编步骤；原页面没有的能力不能为教学方便虚构。长任务可以分段，由用户决定继续下一段或自由练习。

实际走通桌面和窄屏，覆盖错误输入、中断、暂停恢复、Enter/Tab、弹层、重播、减少动态效果和返回正文；根据变化选择用例，不把原项目全部课件场景当作每次必跑清单。隔离练习检查没有真实写调用，真实任务引导则验证其已声明副作用。
