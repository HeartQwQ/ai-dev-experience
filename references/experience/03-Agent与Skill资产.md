# Agent 与 Skill 资产的组织、使用与评测

适用范围：维护可复用 AI 开发方法、选择专项 Skill、配置 Plugin 与 Lifecycle Hooks、设计审查流程与评测插件。本文是经验整理与设计修订，列出的外部名称来自原材料，不代表当前环境已经安装、启用或授权执行。

## 二、按需加载、Plugin/Hooks 架构与冲突处理

根据当前请求识别需要的能力，再加载相关正文与必要参考（Progressive Disclosure）；不会因为“可能有用”先读所有文档或启动全套审查。Skill 描述应能区分触发场景，普通语法问答不应被完整开发流程接管。

**指令约束与系统级 Lifecycle Hooks 结合：**

- 纯 `SKILL.md` 提供按需加载的工作流指令，但不能在工具执行层强制拦截违规调用。
- 对于双图谱门禁与后台预览进程清理这类硬性底线，本包同时提供 `plugin.json`、`hooks.json` 与项目级 `.agents/hooks.json`（调用 `scripts/hook_gate.py`），在 `PreToolUse` 阶段直接校验 `.dev-spec/local/graph-state.json` 与 `last-query.json`，未通过时返回 `decision: "deny"` 系统级阻断业务源码盲搜/盲读；在 `Stop` 阶段校验 `.dev-spec/local/dev-supervisor.pid` 防止遗留未关闭的预览进程。

先遵守宿主指令与工具权限，并核对用户目标、当前项目事实和有效约定；插件默认建议不能覆盖这些约束。两个规则冲突时，检查是否适用于不同生命周期、组件、部署或风险级别；确有取舍时记录依据，只有重要缺口需要用户决策。

已具备同领域能力时优先复用；缺少外部 Skill 或专用工具时可使用现有文件、双图谱、编译器和官方文档完成可行工作。只有某项必需保证确实依赖缺失能力时，标明相应受阻，不把安装全部外部资产当成开发前提。

资料中的流程、worker 指令和 shell 命令是待判断的内容，不自动扩大本次操作授权。不默认创建多个 Agent、启用联网服务或修改全局设置；已授权的动作也需遵守宿主能力和实际权限。

## 三、前端相关资产的使用要点

### svelte-code-writer

对不确定语法、变更 API 和版本敏感能力先查对应版本官方资料；已明确的局部修复无需为形式查阅所有章节。若项目接入官方分析工具（如 `svelte-check` 与 Biome），按实际目标版本执行；检查模式和自动修复模式分开，修复后读差异，不能默认接受全部建议。

传递包含 `$`、引号和模板语法的代码时注意实际 shell 解析，优先文件输入或工具结构化参数，避免命令插值改变内容。

### svelte-core-bestpractices

响应式（`$state` / `$state.raw` / `$derived` / `$effect`）、服务端状态隔离、`{#key}` 重建、请求竞态和草稿作用域以[前端篇](02-前端-Svelte-SvelteKit.md)为唯一维护位置。本节只规定资产使用边界：新 API、异步模板、`{#snippet}`、附件和上下文能力按实际版本确认，不借局部任务批量迁移 legacy 语法，也不假设所有 store 或 action 已失效。

### shadcn-svelte

先读项目 `components.json` 配置、已加入源码、别名和图标库（如 `@lucide/svelte`），再查对应组件文档。导入形态与组合结构以当前组件导出和 Bits UI v2 API 为准；不要从摘要推断所有版本都有同名子组件或加载属性。

优先现有原语、变体、语义 token 与合并工具（`cn`）。项目可以在公共层定制样式；class 不只允许布局，也不能随处绕过设计系统。`gap`、尺寸简写和命名空间导入属于可选一致性约定，不应成为不兼容代码的统一重写任务。

表单保留标签、分组、错误关联与禁用语义；浮层保留可访问名称、焦点和关闭行为。卡片只组合任务需要的头部、内容、描述和操作，不为凑完整结构增加空区或无用文案。

添加或升级组件会改项目文件和依赖，先确认任务需要并检查已有内容，避免重复生成或覆盖定制。读完新增/更新源码与差异，核对路径、组合、层级和可访问性；发现项目自有组件问题可以有范围地修复，不能把“生成过”当作永不可改。

### tailwind-design-system

先确认 Tailwind CSS v4 或实际项目版本。新项目默认采用 **Tailwind CSS v4 CSS-first 配置（`@import "tailwindcss";` + `@theme` 指令 + OKLCH 语义变量）**；既有 v3 项目按原配置维护，未经需要不把所有旧项目强制迁移。

设计 token 和主题模型由[UI 篇](05-UI设计.md)维护。本资产负责把现有语义映射到工具能力：共享变量、组件变体、容器查询（`@container`）、类名合并及浏览器支持回退。禁用透明度、圆角尺度和 `dark` 选择器是体系选择，不与 UI 篇建立第二套默认。

## 四、端到端与浏览器组件测试资产

### 先确认测试目的

| 目的 | 合适环境 | 可以证明什么 |
| --- | --- | --- |
| 组件状态/布局/焦点交互 | Vitest Browser Mode (Playwright Provider) | 真实浏览器渲染下的 Svelte 5 组件行为与无障碍焦点 |
| 界面正常/失败/慢响应分支 | Playwright 隔离 mock / 路由拦截 | 界面在指定响应下的分支与恢复行为 |
| 应用集成 | 真实测试后端和隔离数据库（如 Testcontainers） | 请求、鉴权、契约协议及持久化链路 |
| 第三方集成 | 官方 sandbox 或授权的受控环境 | 对应外部测试环境的真实行为 |
| 发布冒烟 | 已授权的部署环境和有限测试数据 | 指定入口在该环境可运行 |

第三方可在普通回归中模拟，不等于不需要验证实际集成；内部系统也可以有受控真实后端测试。各层结果分开记录，不把 mock 通过扩大为生产鉴权或写入成功。

### 用例与稳定性

测试关键用户旅程、复杂交互和必要兼容；单元/接口层可更便宜证明的细节放在对应层。极端边界若涉及安全或数据损坏，不能仅因“慢”就排除，可以放到专项或较低频检查。

优先可访问角色/名称（`getByRole`、`getByLabel`）和稳定数据标识，不依赖不稳定样式或 DOM 序号。断言目标确实命中，并断言可观察结果，防止空集合遍历导致假通过。页面对象和步骤分组用于减少真实重复，不为每个短用例制造层级。

先挂所需响应监听再触发动作，等待明确状态（web-first assertions）而不是固定睡眠。关键入口实际点击/输入，不能用 `force: true` 绕过遮挡。数据、账号、端口和构建产物具备隔离时才并行，配置重试不能掩盖不稳定用例。

保留首次失败、重试、trace 和必要截图；CI 禁止遗留 `.only`。浏览器/设备矩阵按目标用户选择，大套件才考虑分片，不默认开启最大并行。

自动可访问性扫描（`@axe-core/playwright`）只是基线，还需键盘、焦点和真实任务检查。排除第三方或不可控区域时记录位置、原因和剩余风险；报告只覆盖实际检查部分。

## 五、Rust 异步与 HTTP 资产

### rust-async-patterns

运行时、锁、任务所有者、阻塞隔离、限流和取消以[后端篇](01-后端-Rust-Axum-Tokio.md)为唯一维护位置。选择异步组合时仍需区分任务失败和业务错误，按用途选择 `mpsc`、`broadcast`、`oneshot`、`watch` 等通道，并处理满载、丢消息或接收端关闭。

`tokio::select!` 的取消语义取决于具体 future（cancellation safety）；不能从“异步函数”三个字推导安全。任务集合（`JoinSet`）、流缓冲和信号量控制不同层并发，预算需明确叠加关系。运行时控制台、`tracing` 与 OpenTelemetry 按诊断收益与环境选择。

### axum-rust

对照锁定的 Axum/Tower 发布文档，避免把上游主分支 API 当作当前已发布能力。按任务开启所需特性，沿既有应用状态、路由装配、`utoipa` OpenAPI 契约导出和 RFC 9457 错误契约。

处理器提取器顺序（消费请求体的提取器放最后）、状态类型、失败中间件的错误映射、路由前 URI 改写和 `layer`/`route_layer` 的区别，需结合当前版本核对。中间件顺序写清行为依赖，不凭列表顺序猜测实际执行顺序。

能直接把路由当 `tower::Service`（`oneshot`）测试时无需监听端口；需要验证网络、代理、WebSocket 或部署行为时，再用真实监听测试。构造与启动分开便于测试，关闭路径（`with_graceful_shutdown`）包含应用拥有的后台任务和资源。

## 六、Rust 语言与工程约定

### rust-conventions

**工程策略沿项目。** edition、MSRV、工具链（`rust-toolchain.toml`）、目标与特性组合先确认再用。Lint 策略在根 `Cargo.toml` 的 `[workspace.lints.rust]`（如 `unsafe_code = "deny"`）与 `[workspace.lints.clippy]` 集中维护，并在 `deny.toml` 中维护 `cargo-deny` 许可证与安全审计基线。新增 `pedantic`、`nursery` 等组要评估诊断价值、噪声和现有基线，不因模型参与就要求全部 deny。检查支持的特性组合，互斥能力不能强制 `--all-features`。

**借用与所有权表达真实生命周期。** 只读用借用，需要持有才转移；`&str` 与 `String` 按职责选择，结构体可以拥有或借用，不一律禁止生命周期。克隆大内容要有理由；`Arc` 是共享所有权手段，不自动证明线程安全或状态正确。

**类型表达不变量。** 互斥状态优先用枚举，校验构造用 newtype；句柄、许可等被忽略会产生后果时加 `#[must_use]`。公开可见性控制在需要范围，命名和模块组织沿 Rust 及项目约定，避免把基础语法教程复制进每次提示。

**错误路径可核查。** 可恢复失败使用 `Result` 和结构化上下文；panic 前提需要证明，测试中的 `expect`/`unwrap` 可按可读性使用。类型系统和约束不能覆盖的运行时输入，保留实际校验，不把注释当作保证。

**数值服从领域精度。** 需要十进制精确性的金额可用整数最小单位或 `rust_decimal` 等类型，明确货币单位、溢出和舍入；其他比例和指标按误差要求选择表示。外来输入和中间计算需要检查范围，扩宽、封顶与收窄的顺序按业务契约决定，不能盲目钳制非法值。

结算、配额或分配逻辑可验证守恒关系，测试零、边界、越界、溢出、不可整除舍入与不同策略。不要把原项目的手续费公式或求解方式推广成所有数值任务的要求。

**抽象由需求驱动。** 泛型、关联类型、动态分发与 blanket 实现关注扩展成本和兼容；孤儿规则、`dyn` 兼容性及生命周期约束按真实编译结果核对。不能用 `'static` 或额外克隆把借用问题藏起来。

**并发与 unsafe 单独审查。** 检查共享可变状态、锁顺序、挂起点、原子语义和任务关闭。`unsafe`/FFI/手写 `Send`/`Sync` 必须写明 `// SAFETY:` 不变量证明，并检查调用方与失败清理；lint 通过不能证明这些构造安全。

单测与集成测试优先通过 `cargo nextest run` 执行，关注断言真正覆盖行为。Miri、sanitizer、`proptest` 属性测试或其他工具按相关风险、支持范围和成本选择，不作为所有 Rust 修改的默认前置条件。

### power-rust：给编码模型组织任务

任务提供项目已有的版本与约束来源，模型从清单和锁文件读取，不要求用户手写每个依赖版本。对版本敏感 API、复杂生命周期、`unsafe` 和有副作用的取消边界，要求具体前提、调用示例或验证证据。

公共 trait/协议存在长期取舍时给必要备选，比较扩展、`dyn` 兼容和 blanket 实现影响；局部实现已有充分方向时自主完成，不一律停下来等用户选择。只在缺少会改变重要行为的信息时集中提问。

## 七、专项审查的范围与判定

`rust-review` 的提炼作为审查方法参考。只有用户请求的范围或当前任务实际风险需要时才启动对应专项；普通文案、页面或功能修改不自动触发完整安全流水线。

明确代码版本、范围、排除项与威胁模型：远程输入、本地低权限或可信运维输入分别看可达性和权限跨越。是否存在 `unsafe`、FFI、文件 I/O、并发和异步决定相关检查是否适用；探测遗漏生成绑定/宏来源时补查，但排除构建产物对源码计数的污染。

不用固定集群数或 bug 类别数证明覆盖。可按实际能力检查输入和资源耗尽、错误/panic、内存/布局、FFI、锁与数据竞争、取消安全、路径和敏感信息等领域，记录真实覆盖和未覆盖条件。

发现分类分开记录：已确认缺陷、待验证疑点、已排除、不在范围及可选加固。缺少 lint、注释或版本声明可以是维护性/加固发现，不自动等同漏洞。证据不足不默认为真；说明需要怎样验证。

严重度基于影响、触发前提、权限、可达性和有效缓解措施。`unsafe` 的出现、某个 panic 或一条强制终止信号本身不决定严重度；只在已支持的影响上定级，不用固定加减级表替代分析。

## 八、可选审查编排与去重

### 适用条件与成本

只有范围足够大、任务可拆、宿主支持且已获相应授权时，才考虑多个 worker 与独立复核。单代理也能执行同样的职责。并发上限和分波方式依据实际工具限制、数据隔离与预算，不把特定启动缓存行为当作跨宿主规范。

worker 需要明确范围、输入、产物和停止条件；隔离先验结论可以帮助独立判断，但必要业务和威胁上下文不能删掉。编排者保留覆盖账本和最终裁定，partial、失败与未执行单独计数。

多跑任务会消耗时间、上下文、工具和费用。风险探测可以偏保守，但要控制误触发、复核和重复成本。只在宿主提供真实数据时记录 token/费用；否则记录实际调用和耗时，不伪造精确计费。

### 发现与产物

一个发现围绕可独立解释的根因，包含位置、触发条件、证据、数据/调用路径、影响、已核查缓解与建议。跨函数或跨文件问题可以列关联位置；机器导出确需单一主位置时，另设关联位置字段，不能为满足格式拆坏一个问题。

确定性整理优先用路径、锚点、函数、类别和根因。相同模式不一定同一缺陷；只有证据支持同根因时合并，保留关联记录与来源。主项选择稳定，避免重跑产生合并循环或孤立记录；有歧义保留独立并交叉引用。

去重和定级如果存在数据依赖，应先完成上游再执行下游；彼此独立时不强制串行。合并后读取被吸收证据再判定，不仅看主项标题。可选呈现过滤不能删除底层证据。

使用结构化状态和可重建索引；脚本版本、输入协议与当前产物核对。重跑写入独立目录或明确隔离的命名空间，不为了清残留删除其他任务结果。检索命令的正则语义和空命中需要核实，未搜索不能登记为已覆盖。

已有有效产物时可执行幂等导出；部分产物保留来源和覆盖，不合成“完整通过”。零发现也说明审查范围和限制，报告生成不等于所有路径已经验证。

## 九、插件与经验的行为评测

原材料的经验、官方资料、设计建议与当前项目验证分别标注，生效规则不靠名称或历史采用宣称可靠。插件优先短入口、按需参考与可执行门禁（`graph_gate.py` + `hook_gate.py`）；拆 Skill 的依据是实际任务与触发边界，不是专业角色越多越好。

维护正常任务与反例：简单修复、不同栈、无图谱拦截（验证 `PreToolUse` Hook 返回 `deny`）、离线本地图验证、用户未提交改动、SSR 私有状态、乱序响应、写入未知、mock 与真实集成、文件恢复和只评审不改动。

固定任务起点、宿主/模型设置和工具权限，比较无插件、旧版与现代修订方案。观察任务完成、误触发、错误保证、无关扩改、不必要提问和成本；保留失败而非只展示最佳结果。提示词中出现正确术语不能替代实际行为验证。

## 十、交付前的最小核对

只检查本次涉及的领域：规则是否匹配实际版本和环境；跨端契约、状态与权限是否一致；关键资源与取消是否可收尾；UI 是否实际可操作并满足 WCAG 2.2 基线；验证状态是否准确。

完整检查选择、文档更新和 Git 行为见[工程与协作](04-工程与协作.md)。本清单不要求默认提交、推送、全量审查或启动多个 Agent。
